# Running E00 / 运行 E00

1. Publish the course worker for the current main commit using **Publish course worker**. The GPU workflow resolves the commit tag, pulls the public digest, and checks the source revision before reserving funds. / 先发布当前 main 的课程镜像。实验工作流在预留预算前解析固定 digest 并核对源码。
2. Check the current provider prices for a 5 GB ephemeral container disk, transfer and requests. In **Course E00 GPU validation** on main, enter the total disk hourly ceiling and the per-attempt extras ceiling in integer micro-USD (1 USD = 1,000,000 units). Include billing minimums in extras. Select confirm_paid to authorize that dispatch against the existing course allocation. / 核实临时磁盘、传输、请求及最低计费额后填写上限。单位是微美元，磁盘按整块盘每小时计。
3. The workflow queries secure capacity and GPU prices, preferring an eligible 4090. Each reservation covers 600 seconds on one GPU. The cumulative E00 limit is USD 1 and 1,800 GPU-seconds. Reservations survive retries and cleanup. The software deadline can be exceeded by a provider or runner outage. / 优先选择符合条件的 4090。每次按单卡 600 秒预留，E00 累计上限 1 美元、30 GPU 分钟。中断恢复可能延长计费。
4. Review the Actions artifact named E00-RUN-ATTEMPT. The controller verifies its run, source revision, name and GitHub archive digest, then checks deletion and settles the reservation. Reported usage is a conservative time/rate estimate. The provider invoice remains the billing authority. / 验收核对数值、上传回执和删除证据。账本用量按时间和费率估算，实际扣费以账单为准。

The dedicated broker-state branch holds the campaign budget and attempt journals. A completed E00 dispatch triggers **Recover course E00 allocation** for that run ID and attempt, including after cancellation. Re-running a failed recovery job repeats reconciliation and cleanup. An ambiguous create with zero or multiple matching Pods keeps the reservation open. Inspect the original attempt and provider inventory before resolving it. / 独立恢复按原运行编号和尝试次数定位资源。创建结果不明且找不到唯一对应 Pod 时，保留预留并阻止新租卡。恢复任务可重跑。
